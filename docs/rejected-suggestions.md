# Rejected and deferred suggestions

| Suggestion | Why it was considered | Decision | Reason | Revisit when |
|------------|-----------------------|----------|--------|--------------|
| Split employees / salary / future paystubs into microservices | Future HR domains differ | **Reject** (MVP) | No independent scaling or ownership need; adds deployment and consistency cost | A real service boundary appears |
| Single "total payroll" headline summing all salaries | An eye-catching dashboard number | **Reject** | Summing INR + USD is meaningless | Phase 2 FX with an explicit reporting currency and rate date |
| Build FX conversion alongside the core features | The playbook addendum includes it in the MVP | **Defer** to Phase 2 | Sravan: core requirements first; FX is extra scope | After M9 |
| SQLite (suggested in the brief) | Zero setup | **Reject** | No `percentile_cont`, weaker constraints, differs from prod | — |
| Store `current_salary` on `employees` | Faster reads | **Reject** | Duplicates truth; the partial index on `effective_to IS NULL` makes the join cheap | Measured bottleneck |
| One salary chart mixing all currencies (e.g. avg salary by country on one axis) | Simplest-looking chart | **Reject** | Bars in INR next to bars in USD on one axis mislead | Phase 2 FX reporting currency |
| Send all employee salaries to the browser and chart client-side | Easy with chart libraries | **Reject** | 10k rows of sensitive data over the wire; SQL aggregates are smaller and safer | — |
| Salary-range filter without a currency | Simpler filter | **Reject** | "50k–100k" means different things in INR vs USD | — |
| Cache insights | Faster dashboard | **Defer** | No baseline yet; 10k rows aggregate quickly in Postgres | M8 measurements show a need |
| Countries/departments as DB tables with admin UI | Normalisation | **Defer** | Static list is enough; no requirement to manage them | HR needs to edit them |
| Kubernetes manifests + future-service templates | Playbook suggests them | **Defer** (optional) | Does not serve the HR Manager; only if time remains | After M11 |
| Install gems from an alternative rubygems mirror when rubygems.org is blocked | Unblocks the backend quickly | **Reject** | Routes around the organisation's network policy and trusts an unvetted source | Instead: offline install from Sravan's own rbenv gem cache |
| Keep the generated `config/master.key` + `credentials.yml.enc` | Rails default | **Reject** | No secrets are needed yet; one less key to leak. Production reads `SECRET_KEY_BASE` from the environment | A real secret needs encrypted storage |
| Lower SimpleCov to line-only coverage | Easier to hit 90% | **Reject** | Branch coverage catches untested `if`/`else` paths, which matter for business rules | — |
| Use Faker for seed names | Common choice | **Reject** | Its global RNG makes determinism fragile, and it adds a runtime dependency to production seeding. Fixed name lists + our own `Random.new(seed)` are simpler | Need for much richer fake data |
| Postgres exclusion constraint (`btree_gist`, daterange) against overlapping salary periods | Strongest possible no-overlap guarantee | **Defer** | Needs an extension. The partial unique index + unique start date + the M5 service (row lock, date rule) cover the MVP's single-writer case | Concurrent multi-user editing |
| Add filter/sort indexes now | Expected to be needed | **Defer** to M8 | Index only what EXPLAIN on the 10k seed shows is needed | M8 |
| Separate `salary_revisions` table (3-table design) | Clean split between pay periods and change events | **Reject** (Sravan chose lean) | Revision would be 1:1 with a salary record. Columns on `compensations` give the same answers without a join | Revisions need their own lifecycle (e.g. approvals, multi-step) |
| `paper_trail` gem for the audit log | Standard Rails audit library | **Reject** | Not available offline here, and ~40 lines of `Versioned` covers what we need (create/update, changed fields, actor) with no magic | Need for reify/rollback, associations, or many more audited models |
| DB trigger forbidding UPDATE/DELETE on `versions` | Hard guarantee of append-only | **Defer** | The app already refuses edits (`readonly?`). A trigger would also block the seeder's documented replace-on-rerun | Production with direct DB access by others, or compliance requirements |
| Record a `version` for no-op saves | Complete log of every save call | **Reject** | Noise. Only real changes matter for "who changed what" | — |
| Load all 10k employees and filter in the browser | Instant filtering | **Reject** | Sends every salary to the client, and gets slower as the org grows. SQL does it in ~20 ms | — |
| Sort by salary across currencies | One "highest paid" list | **Reject** | ₹2,400,000 would sort above $240,000. Salary sort requires one currency (API 400 + UI hides the control) | Phase 2 FX reporting currency |
| Mantine combobox `Select` for filters | Searchable, prettier | **Reject for now** | Native selects are accessible by default, work on mobile, and are reliably testable. The lists are short (≤ 40 titles) | Lists grow too long to scan |
| `narrowSymbol` currency display (`$` for all dollars) | Compact | **Reject** | Made CAD/AUD/SGD look like USD. `symbol` shows `CA$`, `A$`, `SGD` | — |
| Trust `setSearchParams(prev => …)` for URL updates | Idiomatic React Router | **Reject** | `prev` is from the last render; quick changes overwrote each other in a real browser. Changes are built from a synchronously updated ref | React Router queues functional updates |
| Separate frontend container (nginx) + backend container | Common split | **Reject** | Two deployables, CORS or a reverse proxy to configure, and cookies across origins. One container keeps one origin | Frontend needs its own scaling/CDN |
| Serve `index.html` from `public/` | Simplest | **Reject** | Rails' static server sends `max-age=1 year`, so users could keep a stale app after a deploy. Served via `FrontendController` with `no-cache` | — |
| `BUNDLE_DEPLOYMENT=1` (frozen lockfile) in the image | Strict reproducibility | **Defer** | The lockfile only lists x86_64-linux (gems were installed offline here); a frozen install would fail on Apple Silicon. Add `bundle lock --add-platform aarch64-linux` when rubygems.org is reachable, then freeze | rubygems.org reachable |
| Keep partial lockfile checksums (79 of 96 computed from local `.gem` files) | Some supply-chain verification | **Reject for now** | Bundler treats any empty entry as needing a rewrite, so boot crashes or frozen mode refuses. Default gems have no `.gem` file to hash | Regenerate the lockfile with rubygems.org reachable (`bundle lock --add-checksums`) |
| Keep the REST insights endpoints planned in the contract | Consistent with the directory | **Replaced** by GraphQL for the dashboard (Sravan's call) | One shared filter input for six widgets; per-field limits. REST stays for the directory | — |
| Postgres `percentile_cont` for the median | Built in, one line | **Reject** | It works in floating point; numeric(14,2) amounts up to 16 digits can lose precision. Row-number median in numeric arithmetic is exact | — |
| One GraphQL request for the whole page | Fewer round trips | **Reject** | The default chart currency depends on the overview's answer; fetching every currency's histogram up front costs ~7× and exceeds the complexity budget | — |
| Apollo Client | Popular GraphQL client | **Reject** | TanStack Query + a 20-line `fetch` wrapper covers caching and retries; no normalised cache is needed for read-only dashboards | Mutations with shared entities |
| GraphiQL from a CDN, or the `graphiql-rails` gem | Quick to add | **Reject** | A CDN runs third-party scripts on the app's origin; the gem needs the asset pipeline (API-only app) and isn't available offline. Bundled from npm instead | — |
| Recharts | Already integrated | **Replaced** by Highcharts (Sravan's call) | More chart types, built-in accessibility module, columnrange. **Trade-off:** Highcharts needs a commercial licence for company use (free for this non-commercial assessment) | Licence not acceptable → Apache ECharts or Recharts |
| Comma-separated multi-values (`country=DE,FR`) | Shorter URLs | **Reject** | Job titles may contain commas, and Rails reads repeated `key[]` natively. The page URL repeats keys (`?country=DE&country=FR`); the API call maps them to `country[]` | — |
| Checkbox groups for multi-select filters | Every option visible | **Reject** (Sravan chose MultiSelect) | 8 countries and ~40 job titles would take too much space; Mantine `MultiSelect` is searchable, keyboard-accessible and shows choices as removable pills | — |
| Multi-select currency in the directory | Consistent with the other filters | **Reject** | Salary range and salary sort need exactly one currency; several currencies would make "50k–100k" ambiguous | Phase 2 FX reporting currency |
| HR types the employee number | Matches some HR processes | **Reject** (Sravan chose auto-generate) | Typos and clashes; the server knows the next free number | Numbers come from another system |
| Next number from `MAX + 1` without a lock | Simplest | **Reject** | Two creates at the same moment get the same number (one then fails). A transaction-scoped advisory lock serialises only number assignment; a spec runs 4 creates in parallel | — |
| A Postgres sequence for employee numbers | Standard | **Reject for now** | The seed inserts EMP-000001…010000 directly, so a sequence would need resetting after every seed run; the lock + `MAX + 1` needs no upkeep | Much higher create rates |
| Hard delete of employees | "Delete" button | **Reject** | Loses salary history and audit; deactivation keeps both and is reversible | Data-retention policy requires erasure |
| Editable hire date | Fix typos | **Reject** (Sravan chose locked) | The hire date starts the salary history; editing it would rewrite a salary record | Correction workflow with M5 |
| Duplicate the validation rules in the browser | Instant feedback | **Reject** | Two copies of the rules drift; the server is the one source and its field errors are shown inline | Forms become large |
| Retry every failed query 3× (TanStack default) | Resilience | **Reject** | GraphQL validation errors and 4xx fail identically every time; only network/5xx are retried, at most twice | — |
